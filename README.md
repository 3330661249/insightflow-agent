# InsightFlow-Agent

一个用于练习 AI 产品边界与工程可靠性的单主题研究工作流原型：输入主题，判断是否需要检索，再生成带来源记录与质量状态的 Markdown 报告。基于 Python、LangGraph、langchain-openai 和 Bocha Search。

该项目展示的是条件路由、外部服务适配、来源保存、失败降级与离线回归测试。它没有上线效果、真实用户评测或生产可靠性数据，也不代表自主研究系统。

## 用户任务与边界

目标任务是让使用者从一个主题得到一份可继续核对的研究草稿，并且知道资料从哪里来、哪些步骤失败、哪些内容还没有证据。

- 需要外部信息：调用搜索，保留结构化来源，摘要与报告使用 `[S1]` 等编号；导出时追加原始来源列表。
- 不需要检索：可生成概念分析，并标注“未检索外部来源”。
- 搜索缺配置、超时、请求失败、空结果或结构异常：返回限制说明，不把错误文本送给模型作为研究资料。
- 摘要或报告生成失败：保留已有检索摘要与来源，以固定错误码说明失败；不输出外部异常的原始内容。

来源编号校验检查“至少有一个引用、引用编号属于本次来源”，仅允许裸编号（如 `[S1]`）；生成正文含 Markdown 链接、HTML 锚点或链接定义时，会舍弃生成正文并保留原始检索资料，来源网址由程序从来源记录追加。它**不验证每句话是否有引用、来源是否真的支持结论、网页是否可信或资料是否足够新**。含有有效编号的报告仍需要人工核对。

## 快速开始

支持 Python 3.12–3.13；本次本地验证使用 Python 3.13.12。依赖锁文件记录本次实际测试环境，包含测试与 lint 工具。

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-lock.txt
```

无需账号或密钥的离线演示：

```bash
python main.py --offline --topic "本周 AI 新闻"
```

离线模式不加载 `.env`，不调用模型或搜索，输出 `unavailable` 状态和一份“未获得可用外部证据”的报告。它用来演示失败路径，不模拟一次成功研究。报告写入 `reports/`，名称带随机标识，重复运行不会覆盖先前报告。

可阅读 [合成格式示例](examples/synthetic-report.md)，其中内容与来源均不构成真实研究证据。

需要真实调用时，将 `.env.example` 复制成 `.env` 并配置自己的服务信息：

```bash
cp .env.example .env
python main.py --topic "本周 AI 产品动态"
```

模型需要 `ZHIPU_API_KEY`、`ZHIPU_BASE_URL` 和所用服务支持的 `ZHIPU_CHAT_MODEL`；搜索独立需要 `BOCHA_API_KEY`。请确认供应商当前可用的模型 ID 和计费设置。示例中的模型名不构成当前可用性承诺。也可不传 `--topic` 后交互输入。

## 控制流与质量状态

```text
输入校验 → decide_search
              ├─ 需要搜索 → collect_info → 结构化来源 / 安全失败码
              └─ 无需搜索 → skip_tool   → 未检索标记
                              ↓
                        generate_report
                              ↓
                    质量状态 + Markdown 落盘
```

| 状态 | 含义 |
| --- | --- |
| `ok` | 本轮有检索来源，模型步骤完成，报告中的引用编号检查通过；仍未验证事实支持 |
| `degraded` | 有可用来源但生成/引用检查失败，或决策曾降级；报告需要进一步整理 |
| `unavailable` | 未得到任务所需证据，或无来源且模型不可用；不提供研究结论 |
| `unverified` | 未检索来源的模型概念分析 |

`errors` 仅包含固定诊断代码，例如 `SEARCH_TIMEOUT`、`SEARCH_NOT_CONFIGURED`、`SUMMARY_UNAVAILABLE`、`CITATION_CHECK_FAILED`。退出码 0 表示流程执行并成功保存，**不表示研究质量合格**；需检查输出质量状态。输入错误返回 2，保存失败返回 1。

## 本地验证

```bash
python -m pytest -q
ruff check .
```

测试默认不读取真实 `.env`，提供合成服务返回，并阻断 socket 网络连接；即使业务代码捕获了网络异常，测试收尾仍会报告意外联网尝试。覆盖整图缺配置、独立搜索配置、空/异常搜索结果、摘要与报告失败、引用编号缺失/未知、来源落盘、离线 CLI、输入校验、重复报告和长主题文件名。

这组测试验证可重复的工程行为，不测真实模型回答质量。真实质量评测尚未完成：需要固定主题集、时效性标签、人工核对的来源与支持关系，以及任务完成率、引用支持率、时延和成本记录。当前没有可公开声称的这些指标。


## 已知限制

- 单主题单轮，不支持持续研究、多轮记忆、网页正文抓取或自主重试规划。
- 模型决策失败时使用关键词规则，不能覆盖所有时效性需求；只接受模型精确输出“是”或“否”。
- 搜索最多读取 3 条摘要，时间窗口固定为一年；即使主题含“本周”，当前也没有严格日期过滤。提供方给出的发布日期会保留，但不验证。
- 检索材料进入提示词时被标记为不可信数据；这不能保证抵御所有提示注入。没有执行网页指令或访问任意网页的工具。
- LLM 单请求超时为 30 秒、最多重试 1 次；搜索超时为 20 秒。没有全流程成本或总时长预算。
- 当前质量控制是缺失证据与引用编号检查，不是事实核验或完整评测系统。
- 已从当前工作树移除旧的未标注生成报告。历史版本仍保留在 Git 历史中，本次没有重写历史。
